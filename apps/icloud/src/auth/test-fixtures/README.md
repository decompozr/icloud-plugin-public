# Scope upgrade regression

Goal before execution: reproduce persisted resource allowedScopes surviving an insertOnly restart, then test the supported merge seeding mode in an isolated SQLite database with real BetterAuth 1.7.7 Passkey/PKCE/consent/token/introspection. Existing access and refresh rights must not upgrade. Anonymous DCR ownership and client scope ceilings must remain enforced.

The owner fixture is a test-only copy of the production composition exposing seed configuration and raw provider handler for ownership denial checks. No production option or runtime configuration is changed. All identities, keys and cookies are synthetic; the HTTP listener binds loopback and the temporary database is removed. This does not prove ChatGPT refresh behavior.

Result: `bun test apps/icloud/src/auth/scope-upgrade.test.ts` passes 1 integration test / 60 assertions. A legacy anonymous client is genuinely registered before the capability change. After new configuration, a fresh client requests and consents to all four scopes; insertOnly still issues only read/write/offline. Merge preserves the resource name, unrelated resource, client metadata and consent rows; fresh explicit consent then produces send access. Already issued access and refreshed reduced grants stay without send, with read intact. The old client remains invalid_scope for send. The supported server-only adminUpdateOAuthClient API rejects the anonymous client's scope update with UNAUTHORIZED, preserving its row; its HTTP route is intentionally not available. No ownership bypass or direct database write is used. Metadata SELECTs inspect only synthetic fixtures. Strict application typecheck passes.

This is an application/provider test, not proof that ChatGPT Refresh starts a new authorization or that its cached tool list updates. No production reconciliation has been enabled.

Additional evidence: explicit accept:false returns access_denied and preserves reduced rights. A valid owner session is asserted, a genuinely session-owned client update succeeds, then the anonymous legacy client update fails UNAUTHORIZED. Canonical nondefault name, accessTokenTtl=2700 and metadata remain unchanged across merge; only allowedScopes and updatedAt differ. The production candidate still lacks reconciliation and remains unsuitable for this fix; no corrected production artifact was built or deployed.

The test-only copy remains solely for reproducing the original insertOnly behavior and checking the provider ownership API without exposing it in production. Both production owner and scope-upgrade integration tests pass together (2 tests / 109 assertions), and strict typecheck passes. This is source/artifact preparation only; no live restart or database reconciliation has occurred.
